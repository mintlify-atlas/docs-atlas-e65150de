This example shows how Claude Dev Kit's `/implement-us` skill generates a **desktop calculator application** using PyQt6 and the `pyqt-mvc` profile. The profile enforces strict MVC separation: a frozen dataclass Model, a `QWidget` View that only emits signals, and a Controller that connects them. Testing uses `pytest-qt` with `qtbot` to simulate button clicks without launching a real display.

    Six scenarios are generated, each testing a single user interaction with the calculator.

    ```gherkin
    Feature: Simple Calculator

      Background:
        Given la aplicación está ejecutándose
        And el display muestra "0"

      Scenario: Sumar dos números
        When el usuario presiona el botón "5"
        And el usuario presiona el botón "+"
        And el usuario presiona el botón "3"
        And el usuario presiona el botón "="
        Then el display debe mostrar "8"

      Scenario: División por cero muestra error
        When el usuario presiona el botón "8"
        And el usuario presiona el botón "/"
        And el usuario presiona el botón "0"
        And el usuario presiona el botón "="
        Then el display debe mostrar "Error: Cannot divide by zero"

      Scenario: Limpiar display
        When el usuario presiona el botón "123"
        And el usuario presiona el botón "C"
        Then el display debe mostrar "0"
    ```
  </Step>

  <Step title="Implement MVC components (Phase 3)">
    Components are generated in bottom-up order:

    1. **`modelo.py`** — `CalculatorModelo` as `@dataclass(frozen=True)`, with `add()`, `subtract()`, `multiply()`, `divide()`, and `execute_pending_operation()` methods. Immutability is enforced at the Python level: any operation returns a *new* instance.
    2. **`controlador.py`** — `CalculatorControlador` connects View signals to Model operations. It maintains `current_input` state and creates new Model instances on each operation.
    3. **`vista.py`** — `CalculatorVista(QWidget)` defines three `pyqtSignal`s (`button_clicked`, `equals_clicked`, `clear_clicked`), builds a `QGridLayout` with 17 buttons, and exposes `update_display()` and `show_error()` methods. No business logic.
    4. **`main.py`** — wires Model → Controller → View into a `QMainWindow`.
  </Step>

  <Step title="Run tests with pytest-qt (Phases 4–5)">
    Unit tests for the Model run without a display (no `QApplication` needed). Controller tests use mock Views.

    ```bash
    pytest tests/unit/ -v --cov=app --cov-report=term-missing
    ```

    Expected result: **14 passed**.

    Integration tests use `qtbot` to simulate button clicks:

    ```bash
    pytest tests/integration/ -v
    ```
  </Step>
</Steps>

## Key code snippet

The `CalculatorModelo` uses `@dataclass(frozen=True)` to guarantee immutability. Every operation returns a new instance rather than mutating state:

```python
# app/presentacion/paneles/calculator/modelo.py
from dataclasses import dataclass
from typing import Optional


@dataclass(frozen=True)
class CalculatorModelo:
    """
    Immutable calculator model.

    All operations return a new CalculatorModelo instance.
    """
    current_value: float = 0.0
    pending_value: float = 0.0
    pending_operation: Optional[str] = None

    def divide(self, a: float, b: float) -> float:
        """Divide a by b. Raises ZeroDivisionError if b is 0."""
        if b == 0:
            raise ZeroDivisionError("Cannot divide by zero")
        return a / b

    def execute_pending_operation(self, new_value: float) -> 'CalculatorModelo':
        """Execute the pending operation and return a new model instance."""
        if self.pending_operation is None:
            return CalculatorModelo(current_value=new_value)

        operations = {
            '+': self.add,
            '-': self.subtract,
            '*': self.multiply,
            '/': self.divide
        }

        operation_func = operations.get(self.pending_operation)
        if operation_func:
            result = operation_func(self.pending_value, new_value)
            return CalculatorModelo(current_value=result)

        return CalculatorModelo(current_value=new_value)
```

The `pytest-qt` integration test pattern uses `qtbot.mouseClick()` to simulate user interaction end-to-end:

```python
# tests/integration/test_calculator_integration.py
from PyQt6.QtWidgets import QPushButton
from PyQt6.QtCore import Qt


def test_full_addition_flow(calculator_app, qtbot):
    """Test the complete flow: 5 + 3 = 8."""
    window = calculator_app
    buttons = window.findChildren(QPushButton)

    button_5 = [b for b in buttons if b.text() == '5'][0]
    button_plus = [b for b in buttons if b.text() == '+'][0]
    button_3 = [b for b in buttons if b.text() == '3'][0]
    button_equals = [b for b in buttons if b.text() == '='][0]

    qtbot.mouseClick(button_5, Qt.MouseButton.LeftButton)
    qtbot.mouseClick(button_plus, Qt.MouseButton.LeftButton)
    qtbot.mouseClick(button_3, Qt.MouseButton.LeftButton)
    qtbot.mouseClick(button_equals, Qt.MouseButton.LeftButton)

    assert window.display.text() == '8.0'
```

<Tip>
Use `monkeypatch.setattr(QMessageBox, 'critical', lambda *a, **k: None)` in tests that trigger division-by-zero error dialogs. Without mocking, `QMessageBox.critical` blocks the test waiting for a user to dismiss the dialog.
</Tip>
