This example demonstrates Claude Dev Kit's `/implement-us` skill generating a **Contacts REST API** with Flask. The `flask-rest` profile applies a three-layer architecture (Routes → Service → Database), the Repository pattern with an ABC interface, and a Mapper pattern for data conversion. The result is 38 passing tests at 94% coverage and a Pylint score of 9.65/10.

## User story

```markdown
# US-055: Contacts REST API

As a frontend developer
I want a REST API to manage contacts
So I can build a contact book application
```

**Acceptance criteria:**

- `GET /contacts` — list all contacts
- `GET /contacts/{id}` — get contact by ID
- `POST /contacts` — create a new contact with name, email, and phone
- `PUT /contacts/{id}` — update a contact (partial or complete)
- `DELETE /contacts/{id}` — delete a contact
- Email format validation
- Required fields: name, email, phone
- JSON responses with correct HTTP status codes
- Health check endpoint at `GET /health`

## Key code snippet

The `ContactCreate` dataclass validates data at construction time using `__post_init__`. This ensures invalid data can never reach the service layer:

```python
# app/models/contact.py
from dataclasses import dataclass
from typing import Optional
import re


def validate_email(email: str) -> bool:
    """Validate email format using regex."""
    if not email:
        return False
    email_pattern = r'^[^@]+@[^@]+\.[^@]+$'
    return bool(re.match(email_pattern, email))


@dataclass
class ContactCreate:
    """Data for creating a new contact."""
    nombre: str
    email: str
    telefono: str

    def __post_init__(self):
        """Validate contact data after initialization."""
        if not self.nombre:
            raise ValueError("nombre is required")
        if not self.email:
            raise ValueError("email is required")
        if not self.telefono:
            raise ValueError("telefono is required")
        if not validate_email(self.email):
            raise ValueError(f"Invalid email format: {self.email}")
```

The Blueprint route catches `ValueError` from the dataclass and returns a 400 response, keeping HTTP concerns out of the domain model:

```python
# app/routes/contacts.py
@contacts_bp.route('/contacts', methods=['POST'])
def create_contact():
    """POST /contacts - Create a new contact."""
    try:
        data = request.get_json()
        if not data:
            return jsonify({'error': 'No data provided'}), 400
        contact_data = ContactCreate(
            nombre=data.get('nombre', ''),
            email=data.get('email', ''),
            telefono=data.get('telefono', '')
        )
        contact = ContactService.create_contact(contact_data)
        return jsonify(contact.to_dict()), 201
    except ValueError as e:
        return jsonify({'error': str(e)}), 400
```

<Tip>
The unit tests for `ContactService` run without starting Flask at all — they call service methods directly. This makes them fast and keeps HTTP concerns isolated to the integration test layer, which uses Flask's `test_client()`.
</Tip>
