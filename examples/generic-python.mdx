This example shows how Claude Dev Kit's `/implement-us` skill builds a **CSV processing CLI tool** using the `generic-python` profile. The profile imposes no specific framework — it favors modular design, a `src/` layout, and pure Python stdlib. The result is a four-subcommand CLI (`convert`, `filter`, `merge`, `stats`) backed by 90 tests, 98% coverage, and a perfect Pylint score of 10.00/10.

## User story

```markdown
# US-057: CSV File Utility

As a data analyst,
I want a CLI utility to manipulate CSV files
So I can automate data processing tasks
```

**Acceptance criteria:**

- `csvtool convert <input.csv> <output.json>` — export CSV to JSON
- `csvtool filter <input.csv> <column> <value>` — filter rows by column value
- `csvtool merge <file1.csv> <file2.csv> <output.csv>` — combine CSV files
- `csvtool stats <input.csv>` — display file statistics
- Descriptive error messages for file validation failures
- Help message with usage examples
- Exit codes: 0 = success, 1 = error

## Subcommand reference

| Subcommand | Input | Output | Error cases |
|---|---|---|---|
| `convert` | CSV file, output path | JSON file | File not found, invalid extension |
| `filter` | CSV file, column, value | Filtered rows to stdout | Column not found |
| `merge` | Two+ CSV files, output path | Merged CSV file | Incompatible headers |
| `stats` | CSV file | Statistics to stdout | File not found |

  <Step title="Review the architectural decision (Phase 2)">
    The skill generates an ADR (`ADR-001-csvtool-modular-architecture.md`) documenting why a modular package beats a monolithic script:

    - A single script violates SRP and cannot be tested per subcommand
    - The `click` framework was rejected to honor the "stdlib only" constraint
    - Each command module is independently testable without invoking the CLI parser
    - `CsvData` is a shared type imported by all command modules
  </Step>

  <Step title="Implement the modular package (Phase 3)">
    Seven Python files are generated in dependency order:

    1. **`csvtool/models/csv_data.py`** — `CsvData` dataclass with `row_count`, `column_count`, and `numeric_columns` properties
    2. **`csvtool/utils/validators.py`** — `validate_file_exists()`, `validate_csv_extension()`, `validate_output_path()`
    3. **`csvtool/commands/convert.py`** — `convert_csv_to_json()` returning row count
    4. **`csvtool/commands/filter_cmd.py`** — `filter_csv()` returning a `CsvData`
    5. **`csvtool/commands/merge.py`** — `merge_csv_files()` validating header compatibility
    6. **`csvtool/commands/stats.py`** — `calculate_stats()` and `format_stats()` using `statistics.mean()`
    7. **`csvtool/cli.py`** — `create_parser()` and `run()` dispatcher, returns int exit code

## Key code snippet

The `CsvData` dataclass uses a `@property` to identify numeric columns at read time, avoiding any storage of pre-computed state:

```python
# csvtool/models/csv_data.py
from dataclasses import dataclass, field
from typing import Dict, List


@dataclass
class CsvData:
    """Represents the content of a CSV file.

    Attributes:
        headers: List of column names.
        rows: List of rows, each row is a dict mapping header -> value.
    """
    headers: List[str]
    rows: List[Dict[str, str]] = field(default_factory=list)

    @property
    def row_count(self) -> int:
        """Return the number of data rows."""
        return len(self.rows)

    @property
    def column_count(self) -> int:
        """Return the number of columns."""
        return len(self.headers)

    @property
    def numeric_columns(self) -> Dict[str, List[float]]:
        """Return columns whose values are all numeric."""
        result: Dict[str, List[float]] = {}
        for header in self.headers:
            values = []
            all_numeric = True
            for row in self.rows:
                try:
                    values.append(float(row.get(header, "")))
                except ValueError:
                    all_numeric = False
                    break
            if all_numeric and values:
                result[header] = values
        return result
```

The `stats` command uses `numeric_columns` to compute averages with `statistics.mean()` — no external libraries required:

```python
# csvtool/commands/stats.py
import csv
import statistics
from typing import Any, Dict
from csvtool.models.csv_data import CsvData
from csvtool.utils.validators import validate_file_exists, validate_csv_extension


def calculate_stats(input_path: str) -> Dict[str, Any]:
    """Calculate statistics: rows, columns, numeric averages, missing values."""
    validate_file_exists(input_path)
    validate_csv_extension(input_path)

    with open(input_path, newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        data = CsvData(headers=list(reader.fieldnames or []), rows=list(reader))

    numeric_stats = {
        col: {
            "avg": round(statistics.mean(vals), 2),
            "min": min(vals),
            "max": max(vals)
        }
        for col, vals in data.numeric_columns.items()
    }
    missing = sum(1 for row in data.rows for val in row.values() if val == "")

    return {
        "file": input_path,
        "rows": data.row_count,
        "columns": data.column_count,
        "column_names": data.headers,
        "numeric_stats": numeric_stats,
        "missing_values": missing,
    }
```
